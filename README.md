# Seedance 2.5 Director Compiler

独立的 Codex skill：先用影视知识与大师作品完成镜头设计，再把锁定设计编译为可直接复制的 Seedance 2.5 原生分镜提示词。

当前版本：`0.1.8`

## 核心架构

1. **导演域**决定拍什么、为何这样拍：戏点、视点、调度、表演、机位、剪辑、节奏、声音、动作美学。
2. **动作执行域**按需补齐：战术因果、方向、路径、接触、惯性、逐拍时间、环境反馈和连续状态。
3. **L1 锁定门**冻结创意：用户锁与确认版优先，编译时不二次导演。
4. **编译域**只做语义保真翻译：模型事实、对白语法、素材职责和原生分镜表达。
5. **活人感表演基线**：角色承担戏点时先对齐注意力/视线，再用自然小动作、呼吸、重心、物件或听者反应承载情绪；按景别取舍，不堆表情部位。
6. **镜头叙事织合**：每个镜头正文先建立当前画面，再把触发、动作过程、联动反应、对白/声音、运镜和结果写成一条可直接想象的连续事件链；只压缩不影响理解的静态重复。

最终提示词沿用原生分镜骨架：

1. `【通用约束栏 · 本 segment 共享】`：按需写 `素材绑定`、`光影色彩风格`、`角色外观`、`场景外观`等原生共享行；摄影机画面质感和环境声底并入光影色彩行。
2. `【本段戏剧任务】`：本版唯一新增的一栏，按“原有处境 → 新处境 → 明确动作或转折 → 结尾对人物关系、情绪或后续行动的结果”写成一条完整因果句。
3. `【本段情节】`：用大白话概括本段起点、变化和终点。
4. `【镜头N】| M:SS-M:SS`：下一行写切镜/技术声明，再用连续散文按画面发生顺序写一个可独立想象的视觉事件。
5. `【收尾约束】`：写本段最后状态和已经确认的结尾约束。

每个 segment 的完整提示词单独放在代码围栏中，以 `【收尾约束】` 结束；音效用 `<音效>`，音乐用 `（背景播放音乐）`。不附带评分、自检表、读库记录或过程日志。

## 已确认合同

- 单段生成时长：4–30 秒。
- 单一连贯场景默认只生成一个 segment；一个 segment 内可以包含多个镜头和多次剪辑。
- 只有用户明确要求多段，或用户给定时长/锁定事件的最低必要时长确实超过 30 秒时，才启用 `SEQUENCE` 和段间交接。
- 单段图片、视频、音频参考素材合计最多 50 个。
- 段首与段尾各保留 0.5 秒稳定区。
- 对白：`角色ID说{逐字台词}`。
- 旁白：`旁白{逐字旁白}`。
- 素材占位符按类型分别编号：`@image1`、`@video1`、`@audio1`。
- 每个素材占位符在整段正式提示词中只出现一次，统一放在 `【通用约束栏 · 本 segment 共享】` 的 `素材绑定` 行；同一素材的多项职责与作用范围合并在该行。
- 本地路径、文件名、URL、上传标签和平台原始 ID 不进入正式提示词。
- 人物可见且承担镜头变化时，镜头正文优先保留视线/注意力落点，并按需要选择最有证据力的自然表演载体；微表情按景别和因果启用，不做固定配额。

其余数值能力、平台字段与保证性行为不作推断。

## 使用

在 Codex 中调用：

```text
$seedance-2-5-director-compiler
把这段剧本设计成 12 秒镜头，并编译成 Seedance 2.5 提示词……
```

常用任务模式：

- `CREATE_AUTO`：同轮给出 L1 和原生分镜提示词。
- `DIRECTOR_CHECKPOINT`：先确认 L1，再编译。
- `COMPILE`：把已有锁定分镜原样编译。
- `SEQUENCE`：在明确多段或用户给定时长/锁定事件的最低必要时长超过 30 秒时，设计段间状态接口。
- `OPTIMIZE`：保留创意结构，只优化提示词。
- `DIAGNOSE`：定位最早根因并返回最小替换块。

### 已有提示词接入 Blender 白模视频

提供原成片提示词与白模预演视频，进入轻量 `OPTIMIZE`：识别代理颜色与角色的对应，保留原角色/场景等素材及规范编号，只增补一次视频引用。白模提供空间、站位、粗走位、构图和摄影机路径的依据；原分镜继续保留运镜表达、连贯叙事、微表情与小动作、动作细节、对白、声音和特效。只适量压缩重复的静态空间说明，粗模动作和识别色不会自动成为最终表演与外观要求。

详细规则位于 [白模参考接入](references/model/previs-reference.md)，仅在这类输入时读取。无需先制作工程交接包或重做 L1；单纯接入参考跳过导演取材与动作重设计，真正重设计仍按需读相关影视库和大师作品。

动作模式：

- `NARRATIVE`：文戏与普通运动。
- `ACTION_LITE`：单次攻击、闪避、碰撞、抓取、跌落或追逐拍。
- `ACTION_FULL`：持续战斗、兵器、1vN、重武器、超能力或密集弹道。

## 知识路由

每次包含镜头设计或重设计时：

- 读取影视索引；
- 实际读取 1–3 个与当前问题相关的影视专项：单一问题读 1–2 个，真正跨域时读 2–3 个；
- 读取大师索引；
- 实际完整读取至少一部相关大师作品；
- 把作品方法转化为具体镜头决定。

当本段重点是表演、活人感、视线关系、微反应或角色小动作时，专项读取优先包含 `表演细节参考库` 与视线/调度/表演弧线中的一项，仍遵守 1–3 项的按需上限；动作因果为主时先保留动作专项，再补最贴合的一项表演或视线专项。

纯编译、语法修复和模型字段诊断会跳过导演取材。普通单场景在内存中完成，不创建项目状态、读取日志或交付包。

知识库存量：

- 44 份影视专项；
- 67 份大师方法论；
- 117 份大师作品分析；
- 67 个大师目录。

`KNOWLEDGE-MANIFEST.yaml` 保存 228 份知识正文的字节数与 SHA-256；`MIGRATION-MANIFEST.yaml` 记录两套来源、保留范围、剔除机制与已确认平台合同。

## 验证

```powershell
node scripts/clean-knowledge.mjs --root . --json
node --test tests/*.test.mjs
node scripts/validate-skill.mjs --root .
python C:/Users/ASUS/.codex/skills/.system/skill-creator/scripts/quick_validate.py .
```

提示词结构可单独检查：

```powershell
node scripts/validate-prompt.mjs prompt.txt
```

维护已有素材编号（包括空缺）的修订样例时，可使用 `node scripts/validate-prompt.mjs --preserve-asset-numbering prompt.txt`；此选项仅放宽连续编号，仍检查一次性引用、规范格式、引用位置与素材总量。

这些校验器只用于 skill 开发与维护，不参与运行时提示词生成；成品提示词没有最终自检阶段。

## 来源边界

- 影视知识和大师作品源自 `seedance-agent-2-5` 的知识语料，经清理后移除旧版提示词样板、装配协议、评分流程和自动写入机制。
- 模型证据与动作执行逻辑参考 `seedance-2-5-prompt-optimizer-action-fusion`；最终成片采用 `seedance-agent-2-5` 的原生分镜提示词形态，并以本项目用户确认合同为最高事实。
- 两套来源仅作为种子材料；本 skill 具有独立名称、版本、运行架构和验证链。
