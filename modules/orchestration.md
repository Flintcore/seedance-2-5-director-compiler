# Director Compiler 运行编排

本文件只负责任务分流、停点与执行成本；写作归 [SOP](prompt-writing-sop.md)，导演取材归 [知识路由](knowledge-routing.md#决策驱动读取与交接)。不要把这些来源各自扩成一套重复流程。

## 一、先定本次还开放什么

依次保留：最新用户锁 → 已确认 L1 → 故事/逐字对白/素材/世界事实 → 有依据的导演选择 → 模型语法 → 标明的必要假设。已有镜号、七块外观或焦段不等于拍法完成；需要选择观看对象、揭示时机、人物策略、走位或表演时就是设计。只是把已定场面说清则是编译。

| 当前输入与改动范围 | 模式/路径 | 实际读取与停点 |
|---|---|---|
| 新剧本、粗分镜、整组重设计 | `CREATE_AUTO`：A→B→C/D→E→F | 取得内置导演地基、运行SOP及当前问题相关完整章节；风格未定再选作品，已选机制沿用；同轮交 L1 与其提示词 |
| 用户要求先讨论/确认设计 | `DIRECTOR_CHECKPOINT`：A→B→C/D→E | 同上，交完整 L1 后等确认；确认后只进入 F |
| 可执行的已确认/全锁设计，仅翻译格式 | `COMPILE`：A→F | 当前 SOP、范本、模板/编译合同；仅实际模式疑难取相应完整单元，不读原文全册；不重选大师或改设计 |
| 局部目光/构图/表演修复，整体策略已定 | `OPTIMIZE`：A→受影响 C/D→E→F | 读相关完整知识章节、所涉完整手册节/例及编译局部；保未改镜、对白、空间，不全场研究 |
| 只换素材号/格式，已锁创意的表达修复 | `OPTIMIZE`：A→F | 读相关 SOP/模型规则及当前稿；不新建设计，不补动作。已有稿增白模只追加映射与职责 |
| 咨询/结果故障/明确审阅 | `DIAGNOSE` / `AUDIT`：A→G | 只读取能回答实际问题的规则或知识；需导演替代方案才进入相应设计路径，不顺带编译 |

多段 `SEQUENCE` 是执行范围，不替代上表的任务路径或确认策略：每段仍按新设计、先确认、纯编译或局部修复推进，共享适用的已读正文与世界状态。新 IR 的 `task_mode` 沿实际路径保存；兼容旧 `task_mode: SEQUENCE` 时，从当前用户要求和 `approval.status` 恢复对应路径，已有 `draft` 不自动视为批准。不另建范围表或强制字段。

局部修复扩展到人物动机、整段情绪弧、观看立场或整体节奏时，升级为设计取材，不用“微调”绕过正文。用户明确全锁则保留，实质矛盾按 [设计判断](design-judgment.md) 提出最小选择；不以新设计为由覆盖用户锁。咨询无制作任务时不新建项目。

### 生成段边界闸门

4–30秒连续戏默认一条生成，镜头数、动作密度和文本长度不构成拆段理由。`SEQUENCE` 只在用户明确多段，或锁定叙事的最低必要跨度确实超过30秒时进入；先去冗余装饰，保事件和逐字台词。不确定是否超长时保持单段。真实分段只交接必要世界状态、动作相位、光声；不把剪辑切点误作生成边界。真实跨独立生成段按[SOP接点](prompt-writing-sop.md#segment-boundary)在同轴侧实质换视角至少30°，保持世界状态但不复刻前段末镜；所需边界留内部，新段正文自足。

## 二、当前阶段做什么

### A. 读戏简报
先定位当前权威原稿/L1及版本，复用戏核、人物目标/阻力、观众落点、初末状态、逐字台词、素材映射与用户锁，再明确本轮开放的改动。涉及素材事实时查看当前实际图像、视频或音频的相关内容；用户已确认的说明与实际观察分开，未读取或当前不可见的范围照实标明，不凭文件名补造内容。既有来源—编号映射沿 [素材职责](../references/model/reference-assets.md) 保存，白模只沿条件入口处理。

在同一内存 Brief 中分清创作任务路径与 [平台模式](prompt-writing-sop.md#1-先选生成模式再解释素材)，确认本轮总长、单/多段范围和当前批准状态；已有权威值优先，缺省沿当前 SOP，不重设项目。利用已有结果，不重写完整历史；只问会改变本轮执行的关键缺口，非关键信息用明确的必要假设推进，不连环追问。只需一句普通状态说明指出当前路径与下一步，不交付新表格。

### B. 影视知识取材
先实际取得 [内置导演地基](runtime-foundation.md)。方向未定或选用外挂时沿 [外接流程](external-knowledge.md)，有既定风格则直接复用；基础及被选完整知识单元足以支撑当前决定，就停止扩读，进入C，不额外读影视索引、总纲或表演基础。尚有具体未决问题才取 [知识路由](knowledge-routing.md) 的对应完整节；已知正文入口可直达，不先通读目录。所选作品首次用于新判断时取得完整作品正文，既定机制复用。具体借法用自然L1中的简短依据交接；采用IR时才映射到 `knowledge_applications`，不为填字段读取整本schema或另建日志。

### C. 镜头导演
直接沿 [自然L1交付合同](runtime-foundation.md#自然l1与扩读边界) 将本场决定落镜：先镜组意图与观看，再人物行动/接收和空间，最后用构图、机位、光声与剪辑承载。普通自然L1不读取整本Director IR；确需机器可读、跨多场持久状态或字段互操作时才取 [IR](director-ir.md) 相应结构。覆盖/调度/表演等仍有未决选择才取 [镜头设计](shot-design.md) 的相关完整节及必要定义，不把该模块全文当每次设计前提。出现真实锁冲突或目标/做法矛盾才读 [设计判断](design-judgment.md) 对应处理节；无矛盾不预读异议流程。

### D. 条件动作设计
`NARRATIVE` 不启动动作母机；`ACTION_LITE` 读 [动作设计](action-design.md) 的短链；`ACTION_FULL` 持续搏斗/武器/超能力沿同模块完整展开战术、接触、动量和后果。C/D 共同确定动作链与覆盖，不先锁慢镜壳再塞一招；已批准动作纯编译则保持。

### E. L1 锁定门
冻结前由 C/D 把本轮开放决定落实到完整 L1：连续画面主干已有具体起幅、行动/接收、摄影与光声依据，锁定事件及逐镜实际对白范围已落镜，动作并行关系和必要发声时间与总长相容；已有决定保留，尚未解决的关键项只回其负责步骤。这是在形成设计时收束，不另开审查轮或用字段齐全代替画面成立。

`CREATE_AUTO` 将本轮 L1 标为 `turn_locked`，同轮按此快照编译；不是用户历史批准。`DIRECTOR_CHECKPOINT` 为 `draft` 并等待，明确确认后为 `user_approved`。含创意修改的 `OPTIMIZE` 更新 L1 版本并交完整当前稿：用户要求先确认、当前仍待确认或锁冲突尚待选择时保留 `draft`；已授权直接修订时用新版 `turn_locked`，明确确认后才标 `user_approved`。只改素材/格式的 A→F 不补造新设计或 L1。多段中的各段沿同一当前确认策略，不因 `SEQUENCE` 绕过等待。锁镜序、时序、逐镜实际对白范围、表演/观看依据、素材及末态；设计变了更新版本，既有批准不自动覆盖新版。

### F. 原生提示词编译
按 [compiler.md](compiler.md)、[SOP](prompt-writing-sop.md)、完整范本和唯一模板保真翻译。已有决定用具体语言表达；关键拍法仍缺则只退回受影响设计，不让元模板替导演猜。纯编译不重新导演；交付前在本阶段按[基础检查](delivery-check.md)核当前成稿，不重新查库、不新增独立阶段或自检循环。

### G. 咨询/诊断
沿 [诊断](diagnosis.md) 区分表达、参考、表演、空间或观看根因。只返回本轮所问结论/最小替换，已对部分不动；新设计方案仍遵守取材与当前批准范围。

## 三、条件协作

普通单场默认单执行者，A–G 是阶段，不是需要分别启动的角色。只有用户明确委派，或长篇/复杂独立子问题有实际并行收益且宿主允许，才按最小职责交接；不默认顺序跑读戏/导演/编译三个子 Agent。额外批评角色仅在明确审阅或具体复杂争议需要时使用。

独立协作者只接当前原文/用户锁、适用来源与必要上游结果，获得本职责的完整正文；不把全历史或“上游已读”当输入替代。影视事实/大师证据不被摘要杜撰。协作不改变 compiler 的模式和用户确认选择。

白模计划/制作、当前 Seedance 工作的 Blender 搭场景或实际白模参考才读 [白模入口](../references/model/previs-reference.md)。制作交一个适用协作者且明确最低必要几何；已有视频只补参考，不反向建模。普通分镜不加载白模模块。

## 四、读取与写入纪律

- 先按上表定本轮范围；必要正文实际取得后才作相应决定。同上下文、同版本且正文可用时复用；只有文件名/摘要或返回截断时补读完整章节/作品，按章节或连续行段取得，不合并大量长文件造成截断重读。
- 新设计保内置基础和实际所需专题/作品取材；原文全册保留供完整来源查询，不作为每次启动成本；局部修订保相关完整节。扩读只为未决问题，不扫整库，也不使用读文件数、字数或思考时长配额。
- 普通单场在内存工作。长篇多场、持续协作或用户要文件才落盘，复用当前权威稿、编号与已定锁，定点更新。
- 不加载原版六环 bundle，不加日常脚本校验、评分卡、读书打卡或额外自检。维护测试才保存真实调用、读取范围、耗时和结果，以区分文件可达、实际读到、方法用上。
