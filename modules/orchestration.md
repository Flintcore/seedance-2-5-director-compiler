# Director Compiler 运行编排

本文件只决定阶段、职责和交接。它不定义最终提示词格式，也不复制影视知识。

## 一、先定权限，再定流程

冲突按以下顺序处理：

1. 用户本轮明确锁定的内容。
2. 用户确认过的 L1 版本。
3. 用户提供的故事事实、逐字对白、世界规则、素材编号与参考关系。
4. 导演域基于影视库和大师作品作出的设计。
5. 编译域的模型能力与语法事实。
6. 为补齐空缺而做、且已明确标注的假设。

锁定项只允许原样继承。若用户提出新修改，生成新的 L1 版本；旧确认版仍保留为上一个基线。编译器只翻译当前锁定版，不在翻译时“顺手优化”镜头。锁定不等于隐瞒新发现的实质矛盾；按 [设计判断](design-judgment.md) 先说明影响与最小修改，涉及锁时等待选择，已告知并接受的同一取舍不重复拦截。

## 二、任务路由

### 生成段边界闸门

先区分“镜头切换”和“生成段切换”：一个 `4-30s` 生成段可以包含多个镜头、多个动作拍点和多次剪辑。单一连贯场景默认只建立一个生成段。

- `SEQUENCE` 只在用户明确要求多段生成，或用户给定时长/锁定事件的最低必要时长明确超过 30 秒时启用。
- “情节有多个节拍”“动作很复杂”“素材较多”“需要保持连续”都不是自动拆段依据；这些内容优先在同一段内通过镜头组织、压缩装饰和稳定状态完成。
- 若时长证据不足以证明超过 30 秒，选择单段模式（`CREATE_AUTO`、`DIRECTOR_CHECKPOINT`、`COMPILE` 或 `OPTIMIZE`），把多个镜头放进同一份提示词。
- 只有确认需要多段时，才在可读的决定、接触完成、落地稳定、门槛穿越或反应落定之后设边界，并把边界状态交给下一段。

先按实际改动范围选任务模式，再选动作模式。用户把请求称为“优化”不自动豁免导演取材：仅转写已有内容才走纯编译；开放表演细化走相关章节，改视点/节奏/关系弧则走导演阶段。对明确局部技术问题的必要异议只实读对应章节，不强制重选大师或新增审查环。

| 任务模式 | 进入阶段 | 交付 |
|---|---|---|
| `CREATE_AUTO` | A → B → C → D → E → F | 同轮给出 L1 与对应提示词 |
| `DIRECTOR_CHECKPOINT` | A → B → C → D → E | 先给 L1，收到确认或修改后再进入 F |
| `COMPILE` | A → F | 将现有锁定 L1 原样编译 |
| `SEQUENCE` | A → B → C → D → E → F | 仅在明确多段或必要叙事超过 30 秒时，交付多段 L1、段间交接状态和逐段提示词 |
| `OPTIMIZE` | A → F；仅当用户允许重做镜头时进入 B | 保留创意结构的提示词优化，或新版本 L1 |
| `DIAGNOSE` | A → G；确认是导演原因后再进入 B/C/D | 最小替换块或针对性重设计 |
| `AUDIT` | A → B/C/D/G | 用户明确要求的审阅结论 |

已有正式提示词加 Blender 白模预演视频，进入 `OPTIMIZE` 的 A → F 素材增补分支，读取 [白模参考接入](../references/model/previs-reference.md)。原提示词直接作为当前创意基线，无需重建 L1、重跑导演或动作设计；只接入参考时由编译角色完成。即使原段为动作戏，也保留已有动作设计而非重新展开动作母机。只有用户另行要求修改镜头或表演设计时，才进入对应导演取材阶段。

明确提出白模计划或实际制作时，同一按需模块负责最少几何范围和单个 Blender 协作者交接；仅计划不连接，已有视频不反向启动建模。普通分镜／动作／表演任务跳过白模模块。该条件分支不改原有六部分、导演确认和单段政策。

动作模式：

- `NARRATIVE`：文戏、对白、情绪、悬念、普通移动；角色承担戏点时保留注意力落点和自然小动作，不把普通移动压成无状态站位。
- `ACTION_LITE`：追逐、跌落、抓取、碰撞、一次攻击/格挡/闪避等短动作链。
- `ACTION_FULL`：持续搏斗、兵器、1vN、重武器、超能力、密集弹道或明确武术编排。

## 三、六阶段主流程

### A. 读戏简报

把输入压成一个可导演的 Brief，不扩写用户没有给出的剧情：

- 这一段发生什么，开始状态与结束状态是什么。
- 谁想得到什么，眼前阻力是什么，采取哪种策略影响谁，当前已知性格/关系/身体条件如何改变做法，本段变化是什么；不为补表演编造隐情。
- 观众在结尾应看懂什么、感到什么、期待什么。
- 场景空间、人物关系、逐字对白、素材编号和用户锁分别是什么。
- 用户给定的总时长、是否明确要求多段、前后段接续和交付模式是什么；未得到超过 30 秒的证据时，段数按 1 处理。

信息足以推进时直接工作；影响核心因果的缺口才标为假设或向用户确认。

读入既有分镜时同时识别意图与实质冲突；触发时按 [设计判断](design-judgment.md) 实读相关知识，集中给镜号、后果与最小修正。需要用户决定时先交建议，待选择后再输出最终提示词；没有问题直接继续，不展示例行检查。明确已授权自动修正时在范围内处理；明确只改引用/格式时不借此补表演。用户只给动作、未锁表演且本轮需要完善分镜时，相关表演章节支撑自然细化，原剧情和关键动作保持。

### B. 影视知识取材

仅在本轮包含镜头设计、镜头重做或创意审阅时进入：

1. 读取 `references/cinema/INDEX.md`。
2. 围绕当前最关键的导演问题，实际读取 1-3 个专项知识文件；单一问题读 1-2 个，真正跨域时才扩到 2-3 个。
3. 读取 `references/masters/INDEX.md` 选片。
4. 实际通读至少一部大师作品正文；方法论总纲不计入“作品正文”。
5. 将借鉴写成“来源中的具体方法 → 本场的变形 → 落在哪个镜头”的设计依据。

纯 `COMPILE`、只改语法或增补素材参考的 `OPTIMIZE`、只查模型字段的 `DIAGNOSE` 跳过本阶段。详细规则见 [knowledge-routing.md](knowledge-routing.md)。

### C. 镜头导演

用 [director-ir.md](director-ir.md) 建立轻量 Director IR，再按 [shot-design.md](shot-design.md) 设计。创建或重做时读 [设计判断](design-judgment.md)，把可读性、摄影条件、剪辑动机和表演相容性用于选择方案；自己产生的问题在开放维度直接解决，不等最终输出后另行自检：

- 先在现有导演前导形成镜头组的剧本信息、由此带来的观众情绪、对白/表演塑造的人物及观看所得；四问统领整组而非逐镜填满。
- 再确定叙事视角、知情范围与情感距离，形成空间关系与主镜骨架；据此选择下列摄影手段，不从焦段或炫技运镜反推故事。
- 在组级意图内形成可讲述的事件与人物过程：正在做什么、想推动什么、阻力/信息如何到达、行动/听说怎样互相作用、留下什么余态；观察或暗示性镜头保持已定的持续状态，不补造转折。再选摄影方案并映射 Director IR，避免参数先占主体。
- 景别、机位、镜头运动、构图、焦点与切点。
- 调度、表演、潜台词、声音与留白。
- 按 [shot-design.md](shot-design.md) 的活人感基线设计贯穿镜头的行为底流，具体刺激改变其节奏、互动或身体状态；按景别取舍，不以无因眨眼、同步反应或动作配额维持所谓活性。
- 当前生成段的段首状态与段尾状态；只有边界闸门通过的 `SEQUENCE` 才建立跨段连续性。

角色的感知判断、目标策略、行动与接收适应沿现有表演路由真实取材；人物行动、视线、听说时机、对手接收与余态先相容成立（无需每镜独立演完一轮）；每镜再用精炼而足够执行的景别/焦距、相对机位与运镜/固定信息承载，不把所有参数逐项展开成主体。开始与结束的身体、持物、接触、空间状态及实际声光照常保留。复杂动作保全发起、路径、接触、反馈和新状态，压缩的是技术赘述而非因果；逐字对白的位置交给编译器，不改变说话时机或声桥。

### D. 条件动作设计

- `NARRATIVE`：跳过动作母机，保留普通动作的方向与结果；若人物表演是戏点，同时保留视线/注意力锚点和自然小动作或身体节奏，沿用 [shot-design.md](shot-design.md) 的软默认。
- `ACTION_LITE`：调用 [action-design.md](action-design.md) 的轻量链，只展开会影响生成结果的方向、接触、惯性和恢复。
- `ACTION_FULL`：调用完整动作链，明确战术目标、逐拍因果、空间方向、受力后果、连续状态和段尾姿态。

动作美学仍由导演域决定；时间、惯性、方向、接触与连续性由动作模块具体化。对新设计或授权动作重做，C与D在锁定L1前共同确定交锋链、真实速度、覆盖和切点；D发现原时码把快速一招拖成数秒时，回写同一设计并重配开放时序，不将“摄影已排好”误当用户锁，不新增审查轮。纯编译仍保留已批准时序，实质冲突按A处理。反应、回撤和下一次出手可重叠，动作中切镜承接动量，恢复是身体过程而非每次必须停稳。

### E. L1 锁定门

L1 是导演域与编译域之间唯一的创意交接面。

- `DIRECTOR_CHECKPOINT`：状态为 `draft`，等待用户确认；确认后标记 `user_approved`。
- `CREATE_AUTO`：将本轮展示的 L1 标记为 `turn_locked`，同轮编译严格使用这份快照。它不冒充用户历史确认版，用户后续修改立即生成新版本。
- 已有确认版：原样载入 `user_approved`；任何设计变化都先形成新 L1，随后再编译。

编译前冻结镜头顺序、时间关系、逐字对白及跨切的逐镜原文范围、素材绑定、表演意图、动作结果和段尾状态。素材来源 ID 只用于内部映射；正式提示词由编译器另行分配一次性规范占位符。

### F. 原生提示词编译

把当前已解决或用户已接受取舍的锁定 L1 交给 [compiler.md](compiler.md)；若此时才发现新的实质冲突，定点回到 A 的必要异议，不把互相排斥的要求包装成成立，也不重跑完整流程。编译器可以消歧、压缩和绑定素材，但不新增镜头、不改变戏点、不交换动作顺序、不改写逐字对白。编译时先保留每镜的连续画面脊柱，再把字段织回一段自然语言；动态空间锚点、反应和切换因果按理解需要落回镜头正文。最终采用 [主模板](../references/model/nine-layer-schema.md) 的六部分合同：每镜光影、现场声句在正文末，逐字台词按每镜实际听到的范围以中文双引号嵌入该镜正文，跨切续说点名原声源且保留本镜续句，不将后镜词前置到首镜，情绪与动作默认在引号外，长对白内部标注只按必要位置使用；结束时身体和声画状态在末镜结束，无额外尾栏。无外部素材也保留素材绑定节；全局约束从既有本段共用事实提炼，缺额外条件就作空项声明，动态空间与事件仍在镜头中，不新增流程或把初始脚位锁满全段。情绪总控由既有导演策略投影，不新增IR属性或补做表演分析。

### G. 结果诊断

从成片症状回溯到最早原因：

- 若是语法、绑定、时序表达或复杂度问题，直接返回最小编译替换块。
- 若是镜头逻辑、表演、空间或动作因果问题，返回对应 L1 修改点；经锁定后再重编译。

## 四、角色交接

需要并行能力时，最多使用三种清晰角色，且按顺序交接：

1. **读戏/空间**：产出 Brief、人物位置和连续状态。
2. **镜头导演**：读取知识并产出 Director IR / L1。
3. **编译器**：只接收锁定 L1 与模型证据表。

额外批评角色只用于用户明确的 `AUDIT` 或真正复杂的设计争议。任何角色都不得越过用户锁。

## 五、速度纪律

- 普通单场景全程在内存工作，不创建工程目录、中间稿、读库清单或过程日志。
- 影视库按问题选 1-3 个专项；导演任务不得零读取，读够改变决定的材料后即停止扩搜。大师作品仍需至少一部全文。
- 不加载旧版装配协议、环形 bundle、历史提示词样板或重复检查层。
- 不把机械校验、评分卡、覆盖率、通过/失败结论附到最终提示词。
- 只在长篇多场、跨轮迭代或用户明确要求时写项目文件。
