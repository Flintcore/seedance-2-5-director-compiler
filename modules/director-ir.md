# Director IR：导演域的轻量交接格式

Director IR 保存“为什么这样拍、具体拍什么、镜头结束后留下什么状态”。它是导演思考与 L1 的结构化底稿，不是 Seedance 提示词，也不承载平台语法。

机器可读约束见 [director-ir.yaml](../schemas/director-ir.yaml)。日常单场景可在内存中维护，无需落盘。

## 一、最小结构

```yaml
meta:
  segment_id: S01
  l1_version: 1
  duration_s: 12
  task_mode: CREATE_AUTO
  action_mode: NARRATIVE

authority:
  user_locks: []
  story_facts: []
  exact_dialogue: []
  reference_assets: []
  assumptions: []

drama:
  premise: "本段实际发生的事"
  objective: "人物当下目标"
  obstacle: "可见阻力"
  turn: "本段不可逆变化"
  audience_landing: "结尾要让观众看懂并感到什么"

continuity:
  entry_state: "人物/物品/空间/光线/声音的进入状态"
  exit_state: "本段结尾状态；仅在多段任务中供下一段继承"

visual_strategy:
  viewpoint: "摄影机站在谁的认知或情感一侧"
  master_shot_logic: "用什么主镜骨架承载戏点"
  rhythm: "何处积累、何处转折、何处停留，已定主情绪的节奏与温度"
  look_and_sound: "全段成像质感、承担事件或表达作用的光色与现场声音策略，含有意藏露、持续关系和已定情绪边界"

knowledge_applications:
  - source: "references/cinema/... 或 references/masters/... §具体段落/场景"
    principle: "来源中的因果方法"
    transformation: "为本场做出的变化"
    applied_to: [SH01]

shots:
  - id: SH01
    time: "00:00.0-00:04.0"
    function: "这一镜的事件作用或表达作用，亦可持续已有状态与意味"
    image_action: "可读的完整画面事件链：当前构图/关系→触发→主动作→联动反应→结果"
    camera: "景别、焦距、相对主体的水平方位与机位高度、平视/仰拍/俯拍、运镜或固定状态；视点、焦点及运动动机融入其中"
    staging: "人物和关键物的空间关系、注意力/视线落点、头眼身关系及出入画"
    performance: "可观察的注意力、行为、控制和反应，按景别取舍"
    sound: "对白、环境声、关键音效或有意留白"
    transition: "为什么在这里开始/结束/切换"
    end_state: "这一镜交给下一镜的状态"

action: null

approval:
  status: turn_locked
  compiled_from_version: 1
```

镜头数量由戏点和时长决定，不为填格式强拆镜头。一个 `segment_id` 可以包含多个镜头；字段没有改变画面结果时可用一句合并表达。先形成连续的画面因果链，再映射到字段；字段之间的边界只服务内部校准，不应让成片叙事变成碎片。用户锁、逐字对白、进入/退出状态不可省略。

## 二、字段边界

### `authority`

- `user_locks`：原样保存用户点名锁定的镜头、风格、角色行为、素材关系或禁止变更项。
- `story_facts`：输入中已经成立的剧情、人物关系、世界设定。
- `exact_dialogue`：保存角色名、逐字文本和所属镜头，可选记录表演口径；语法包装留给编译器。
- `reference_assets`：保存素材类型、内部来源 ID、用途和它绑定的对象。来源路径或文件名只留在内部 IR；L1 使用语义标签，编译器再生成一次性的 `@imageN / @videoN / @audioN` 占位符。单段总素材数遵守已确认的 50 上限。
- `assumptions`：只放推进设计所需但尚未由用户确认的最小假设，不混进锁定项。

### `drama`

`premise` 复述事件；`objective` 和 `obstacle` 产生可拍冲突；`turn` 组织本段结构，不分摊为每镜必须新增转折；`audience_landing` 包括理解、感受及有意保留的疑问。镜头取舍同时看事件与表达作用：基础情节不变但潜台词、人物理解、情绪距离、主题联系或观看体验受损，仍有保留理由；详见 [表达价值](shot-design.md)。不将镜头删减测试机械套到镜内光影等载体。

### `continuity`

进入/退出状态至少覆盖当前任务中会跨镜变化的对象：人物位置与朝向、当前注意力/视线目标、手中物、服装/伤势、环境变化、主光方向、关键声音、尚未完成的动作或表演节奏。多段任务中，前段 `exit_state` 是后段 `entry_state` 的事实来源。

### `visual_strategy`

只记录统领整段的导演选择：视点、主镜框架、节奏曲线、光色和声音态度。`rhythm` 与 `look_and_sound` 已能承接主情绪、节奏温度和已定的情绪对照，编译器据此投影到情绪总控，不为新标题新增属性。已有字段也承接表达意图与藏露选择，不加暗示字段；具体到某个人/某镜的明暗、反射或遮挡关系留在 `shots.image_action` 等现有画面描述中，不以共享风格替代差异。每镜真实声源、远近、时机与余响由现有 `shots.sound` 承接。

### `knowledge_applications`

这是创意依据，不是读库日志。每条必须说明：

1. 来源的具体段落或作品场景。
2. 借用的是因果方法，而非“像某导演”这类表面标签。
3. 为当前人物、空间和时长做了什么变形。
4. 最终落实到哪些镜头。

通常保留最能解释核心选择的少量条目；实际读取要求由知识路由控制。

### `shots`

每镜必须有一个清晰 `function` 和可见的 `end_state`，并先作为一个可独立想象的连续画面事件来设计；这些是内部 L1/IR 字段，不作为成片提示词的新栏目。`image_action` 先写当前构图、开始体态、触发、动作过程、联动反应和结果，保留该镜光源实际作用及有实体原因的变化或稳定；锁定设计没有对应事件时，写明正在持续的观察、停留或状态，不补造剧情。`camera` 交代本镜景别、焦距、相对主体的方位与高度、平仰俯、运镜或固定状态，再写摄影机如何回应事件；`performance` 写可观察行为，不用抽象情绪词替代动作。人物可见且承担本镜戏点时，优先写清视线/注意力落点与时机，需要时用自然的小动作、呼吸、重心、手/物件或听者反应承接；景别、类型或锁定状态不适合时，用有动机的姿态、距离或静止承接。眼睛不可见时可明确头身朝向与世界空间目标；既定遮挡或暗部有意保留心理不透明时，不为解释情绪另补泄露动作。`sound`、`transition` 和 `end_state` 仍与这条画面因果链对应：声音写清发生处与实际声源，持续环境声不因没有新增点声而删除；`transition` 可写镜内延续/不切，发生切换时写出前一状态的结果与新视点的首个状态；`end_state` 留下可继承的身体、持物、接触、动作与关系。编译时声源进入每镜末的现场声句，精确对白来自 `authority.exact_dialogue` 并只落在独立台词行；没有台词就省略该行。

### `action`

`NARRATIVE` 保持 `null`。`ACTION_LITE` / `ACTION_FULL` 使用动作模块补充战术目标、空间方向、逐拍因果、惯性、接触后果与恢复状态；审美决策仍留在 `visual_strategy` 和对应镜头。

### `approval`

- `draft`：等待用户确认。
- `turn_locked`：自动创作同轮编译所使用的冻结快照。
- `user_approved`：用户明确确认的版本。
- `revision_requested`：用户已经提出修改，禁止继续以旧版编译。

编译结果需记录其 `compiled_from_version`，以免多轮对话串用旧镜头。

## 三、IR 到 L1

L1 是 IR 的可读投影，保留以下内容：

1. 核心意图与观众落点。
2. 锁定事实、逐字对白和素材绑定。
3. 段首/段尾连续状态。
4. 导演总策略及具体借鉴。
5. 按时间排列的镜头表。
6. 条件动作链。
7. 版本与锁定状态。

平台字段、成片提示词标题和编译句式不进入 L1。编译器从 L1 取值，把镜头字段织回一段自然语言并在其后独立呈现逐字台词，不反向修改 IR 的导演决定。五部分的新标题是输出投影，不改IR结构；段首/段尾状态落到相应镜头，未使用外部素材也不虚构来源。
