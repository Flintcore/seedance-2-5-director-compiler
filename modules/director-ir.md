# Director IR：导演域的轻量交接格式

Director IR 保存“为什么这样拍、具体拍什么、镜头结束后留下什么状态”。它是导演思考与 L1 的结构化底稿，不是 Seedance 提示词，也不承载平台语法。

机器可读约束见 [director-ir.yaml](../schemas/director-ir.yaml)。日常单场景可在内存中维护，无需落盘。

## 一、最小结构

```yaml
meta:
  segment_id: S01
  l1_version: 1
  duration_s: 12
  task_mode: CREATE_AUTO # 多段仍保存实际任务路径；SEQUENCE 仅兼容旧值
  action_mode: NARRATIVE

authority:
  user_locks: []
  story_facts: []
  exact_dialogue: []
  reference_assets: []
  assumptions: []

drama:
  premise: "本段实际发生的事"
  objective: "人物当下目标"
  obstacle: "可见阻力"
  turn: "本段不可逆变化"
  audience_landing: "结尾要让观众看懂并感到什么"

continuity:
  entry_state: "人物/物品/空间/光线/声音的进入状态"
  exit_state: "本段结尾状态；仅在多段任务中供下一段继承"

visual_strategy:
  viewpoint: "观众依附谁的所知与情感，关键变化何时可知、何时有意隐藏；观察位置另在各镜实现"
  master_shot_logic: "用什么主镜骨架承载戏点"
  rhythm: "按类型组织积累、快速追压、短促冲击、转折与必要停留；动作速度、运镜速度和剪辑密度分别决定，服从已定体验"
  look_and_sound: "全段成像质感、承担事件或表达作用的光色与现场声音策略，含有意藏露、持续关系和已定情绪边界"

knowledge_applications:
  - source: "references/cinema/... 或 references/masters/... §具体段落/场景"
    principle: "来源中的因果方法"
    transformation: "本场取舍及其可见/可听依据与发生时机"
    applied_to: [SH01]

shots:
  - id: SH01
    time: "00:00.0-00:04.0"
    function: "本镜对镜头组意图的贡献：事件、人物、情绪、空间或表达作用，可铺垫或持续意味"
    image_action: "本镜连续画面主干：具体起始构图中的行动、听说互动、摄影响应与结果；将已选表演和观看方法兑现于此"
    camera: "足够执行本事件的景别、焦距、相对机位及运镜/固定状态；必要构图、光学可见结果与事件响应，避免参数堆砌"
    staging: "人物和关键物的空间关系、注意力/视线落点、头眼身关系及出入画"
    performance: "人物策略与触发式习惯怎样落为持续行为、注意力、听说互动和反应；按可见性取舍并延续身体条件"
    sound: "对白、环境声、关键音效或有意留白"
    transition: "为什么在这里开始/结束/切换"
    end_state: "交给后镜的世界状态与未完相位；是继承依据，不是另写一段镜尾清单"

action: null

approval:
  status: turn_locked
  compiled_from_version: 1
```

镜头数量由戏点和时长决定，不为填格式强拆镜头。一个 `segment_id` 可以包含多个镜头；字段没有改变画面结果时可用一句合并表达。先形成连续的画面因果链，再映射到字段；字段之间的边界只服务内部校准，不应让成片叙事变成碎片。用户锁、逐字对白、进入/退出状态保留为事实依据，不要求在每镜全部重述。

时码、源音画测量及工具关键帧属于内部预算/执行依据，不直接导出为镜头正文的逐秒命令。正式标题保留粗略镜长；镜内将先后/同时、对白原词切点与情绪变化转成事件关系，原台词/画面文字中的时间原文除外。

## 二、字段边界

### `authority`

- `user_locks`：原样保存用户点名锁定的镜头、风格、角色行为、素材关系或禁止变更项。
- `story_facts`：输入中已经成立的剧情、人物关系、世界设定。
- `exact_dialogue`：保存角色名与完整逐字原文；单镜用 `shot_id` 指明归属，跨镜可用 `fragments: [{shot_id, text}]` 保留每镜连续原文片段，各片段按序拼回须等于完整 `text`。镜号对应已有 `shots.id`，不把起声镜ID当整句仅属于首镜。`delivery` 记录必要时机、画内/画外与表演。已有L1逐镜范围直接复用；这是内存交接信息，不新增每次必写表格或文件。语法包装留给编译器。
- `reference_assets`：保存素材类型、内部来源 ID、用途和它绑定的对象；已有规范编号存入可选 `output_placeholder`，例如 `@image4`，与 `source_ref` 一起交接，保留空号和原映射。新素材尚未编号可省略该属性，编译器仅为新来源按本类型最高已有编号续号。来源路径或文件名只留在内部 IR；L1 使用语义标签，不展示编号并不删除内部映射。单段总素材数遵守已确认的 50 上限。
- `assumptions`：只放推进设计所需但尚未由用户确认的最小假设，不混进锁定项。

### `drama`

`premise` 复述事件；`objective` 和 `obstacle` 产生可拍冲突；`turn` 组织本段结构，不分摊为每镜必须新增转折；`audience_landing` 包括理解、感受及有意保留的疑问。镜头取舍同时看事件与表达作用：基础情节不变但潜台词、人物理解、情绪距离、主题联系或观看体验受损，仍有保留理由；详见 [表达价值](shot-design.md)。不将镜头删减测试机械套到镜内光影等载体。

目标/阻力决定人物此刻采取的策略；潜台词是策略与公开说法的关系，不是额外剧情。长期习惯、关系和声线身份来自既有角色资料，仅把当前触发后影响行为的部分带入 `shots.performance` 与 `shots.sound`。系列档案按需内部复用，继续使用现有故事事实/素材职责与镜头字段，不增加必填人物传记、角色卡或最终栏目。

### 段级策略与逐镜执行

先用现有 `drama` 与 `visual_strategy` 承接镜头组的剧本信息、观众情绪、对白/表演塑造人物与观看所得，再决定叙事视角、知情范围和情感距离。无需新建四问字段或组表；明确多个意义组时可在原导演前导和对应 `shots.function` 指明承接。镜头组不是自动生成段，单镜也不必独立完成完整剧情；本镜作用按前后文成立。随后选择表演调度与摄影/光声，反向修正只在开放范围内进行。

`drama` 与 `visual_strategy` 说明整段人物想取得什么、用什么策略应对以及观众怎样经历；`shots` 说明这些选择在当前时刻怎样被执行、接收和改变。段级的“想说服同伴”与镜内的“看到同伴动摇后继续解释”是有效分层，不因去重删掉任一层的职责，也不把整段策略逐镜重抄。编译时从现有 `drama`、故事事实和 `shots.performance` 提炼本段需要的各角色目标、顾虑或认知与策略，保留到【本段目标】，不以“只写可见动作”删除已定心理；详略和藏露沿[主模板](../references/model/nine-layer-schema.md)。这只是确认内容的投影，不为凑心理新增动机。具体动作、切点与时码只保留一套相容的执行安排；冲突触及锁定内容时走已有设计判断。继续使用现有字段，不新增人物策略卡、动作链表或成稿栏目。

### `continuity`

进入/退出状态至少覆盖当前任务中会跨镜变化的对象：人物位置与朝向、当前注意力/视线目标、手中物、服装/伤势、环境变化、主光方向、关键声音、尚未完成的动作或表演节奏。多段任务中，前段 `exit_state` 是后段 `entry_state` 的事实来源。

### `visual_strategy`

沿已有 `look_and_sound` 保存总体照度/亮暗分布、光源在画内或画外、人物进出光区的显露与消失；它们与光向同属交接，不新增字段或数值配额。`shots` 的表演可见范围、取景与实际受光必须相容，不让编译器为看清脸覆盖暗部决定。

本场选用的光影方法按[SOP设计交接](prompt-writing-sop.md#lighting-design-transfer)落实：`knowledge_applications.transformation`说明当前光源/遮挡、脸或身体朝向与摄影机观察侧的取舍，`shots.image_action`直接承载可见亮面、阴影形状与随行动的变化；`camera/staging`与之为同一套关系。只在该方法决定画面时展开，不新增字段、每镜光型表或固定暗侧机位。编译须取得这些已定结果，而不是凭来源名重新选灯位。

只记录统领整段的导演选择：视点、主镜框架、节奏曲线、光色和声音态度。`rhythm` 与 `look_and_sound` 已能承接主情绪、节奏温度和已定的情绪对照，编译器据此写入本段目标中的情绪、成像与摄影策略（不设全段镜头焦距）；固定世界灯位/照向/色光/反差写入环境，不为新标题新增属性。已有字段也承接表达意图与藏露选择，不加暗示字段；具体到某个人/某镜的明暗、反射或遮挡关系留在 `shots.image_action` 等现有画面描述中，不以共享风格替代差异。每镜真实声源、远近、时机与余响由现有 `shots.sound` 承接。

### `knowledge_applications`

这是创意依据，不是读库日志。每条必须说明：

1. 来源的具体段落或作品场景。
2. 借用的是因果方法，而非“像某导演”这类表面标签。
3. 为当前人物、空间和时长做了什么变形。
4. 最终落实到哪些镜头。

通常保留最能解释核心选择的少量条目；实际读取及本场应用按 [决策驱动交接](knowledge-routing.md#决策驱动读取与交接)。`transformation` 说明选择带来的具体观看结果，`applied_to` 指向实际镜号；并非填写越多越好。既有世界状态可作为画外连续性依据，但观众得知它的时机须由 `image_action`、`sound` 和 `transition` 的实际显露/隐去承接，未拍到不冒充已交付。

采用风格参考时，按 [六维转译](../references/cinema/导演视觉风格参考库.md#style-transfer) 将来源机制、主辅范围和本场取舍放入上述 `principle/transformation/applied_to`，具体决定接入既有 `shots` 与 `look_and_sound`；不另设六栏风格表。没有改变的维度复用，来源说明留在设计层，编译交接保留动作与声画依据。

### `shots`

同一镜只有一份相容的场面决定：`image_action` 把实际起始画面、人物事件与摄影响应讲成可想象的连续过程；`camera/staging/performance/sound` 补充其必要参数、依据或已定细节，不再各编一版动作。功能和取材理由留设计层，`end_state` 保存含画外对象的接续依据。编译按 [信息用途](prompt-writing-sop.md#scene-first-handoff) 投影，不逐字段拼接全文。主干只剩“受到打击、清楚可见”等结果词，而具体路线/取景散落各栏时，设计环先把已有决定合回主干；尚缺决定则在开放范围内定好再交接。

完整事件可由一组镜头合成，不要求每个镜头分别走完准备、接触、反应、恢复。`end_state` 可是快速运动中的相位及动量，下一镜接住它；先组织动作交锋链再定镜头时码，不把字段顺序当事件必须串行等完的日程。

每镜有承接组级意图的 `function` 与可继承的 `end_state`；先确定当前可见过程及其前后关系再映射字段，完整人物事件可跨镜成立，不强塞进每镜。`image_action` 承载开始时正在做什么、阻力/触发、行动与听说互动、调整和余态，观察/留白也可持续已定状态；`performance` 承载策略、触发式习惯和贯穿其间的自然行为，不变成关键帧表情表。`camera` 以足够执行的景别/焦距、相对机位、必要构图和运动回应这个事件，不用参数长度证明完整。首帧的站位、持物/接触与注意力落点让事件马上成立，切镜不重置这些事实。

可见性按景别、光线与身体结构取舍：隐眼、背影和非人角色沿已有通道，故意隐藏的心理继续隐藏；静止同样可以是已定行为。`sound` 保留真实声源、当场表达、听说时间和跨切延续，声线身份不替代具体策略；`transition` 说明新视点接到何种状态，也可以不切；`end_state` 继承身体、持物、接触、关系和未完成的呼吸/动作负荷。实际受光关系与变化仍由镜内实体承载。编译时局部光影/声源随事件发生，共享层进入环境/声音，精确对白来自 `authority.exact_dialogue`，按既定切点将本镜实际听到的连续片段以中文双引号嵌入该镜正文，续说镜也明确原声源；完整 `text` 是原文来源而非首镜应印出的全文。情绪、动作与语气默认放在引号外。长对白确需定位中途变化时，编译才按需插入 `【非发声表演说明】`，移除说明后的原文逐字不变；必要时机保留在 `delivery`，跨镜词句归属沿已有L1或可选 `fragments` 交接，装配时保留分配，不合回首镜全文。

起始取景与动态构图落在现有字段：camera记录本镜焦距、机位、取景范围和主要运动；staging说明起始主体/物件的画面左右、实际前中后景、裁切、遮挡和世界锚；image_action写人物/相机何种变化怎样重排画面，end_state交出结果或未完相位。三分、对角线等选择依据保留在设计中，装配按[构图落笔](prompt-writing-sop.md#screen-composition)译成人与物的具体位置。只写“近景/三分构图/在房间左边”不足以完成这项交接；无需新增字段、卡片或落盘文件。

### 镜头与节拍边界

`shots.id` 对应一个连续摄影镜头，不对应每次情绪变化、动作阶段或注意交接。一个镜头可以容纳多个节拍；若确有画面切换，就按已定切点交接镜号，而非把数次切镜藏在一个镜号内。输入的“分镜”编号若混用了镜头与节拍，先按明确的连续拍摄/切换描述理解；已锁切点保持，只有含混之处影响实际方案时才走既有设计判断。纯编译保留确认 L1 的镜头划分，不借规范编号新增切镜或重排时序。

### `action`

`NARRATIVE` 保持 `null`。`ACTION_LITE` / `ACTION_FULL` 使用动作模块补充战术目标、空间方向、逐拍因果、惯性、接触后果与恢复状态；审美决策仍留在 `visual_strategy` 和对应镜头。

### `approval`

- `draft`：等待用户确认。
- `turn_locked`：自动创作同轮编译所使用的冻结快照。
- `user_approved`：用户明确确认的版本。
- `revision_requested`：用户已经提出修改，禁止继续以旧版编译。

编译结果需记录其 `compiled_from_version`，以免多轮对话串用旧镜头。

多段是执行范围，`meta.task_mode` 新记录仍沿本段实际任务路径；旧 `SEQUENCE` 值按 [运行编排](orchestration.md) 恢复当前路径与批准策略。含创意的局部修订同样递增 `l1_version`，沿本轮确认策略交完整 L1 并冻结新版，不让旧 `user_approved` 自动批准已修改内容；纯素材/格式转写不补造新设计版本。

## 三、IR 到 L1

L1 是 IR 的可读投影，保留以下内容：

1. 核心意图与观众落点。
2. 锁定事实、逐字对白和参考绑定。
3. 段首/段尾连续状态。
4. 导演总策略及具体借鉴。
5. 按时间排列的镜头表。
6. 条件动作链。
7. 版本与锁定状态。

平台字段、成片提示词标题和编译句式不进入 L1。编译器从 L1 取值，把镜头字段与逐字对白织回同一段自然语言；对白以中文双引号嵌入发生位置，不反向修改 IR 的导演决定。七块标题是输出投影，不另建输出专属 IR；已有跨镜发声分配可由稀疏的 `fragments` 承载。段首/段尾状态落到相应镜头，未使用外部素材也不虚构来源。

编译时每个segment自足复述其必要起态、空间和布光，不把entry/exit的跨段指代抄入正式提示词；段间相机接点按SOP合同内部核对。每镜image_action含当前可见受光，look_and_sound保存固定世界灯位，角色转身与换相机只改变相应受光/投影。
